# 风险缓解、监控与管理计划（RMMM）

负责人角色：项目经理

## 1. 风险识别

| 风险类别 | 风险描述 | 影响范围 | 发生概率 | 严重性 | 备注 |
|---|---|---|---|---|---|
| 需求风险 | 项目需求不明确或变更频繁 | 项目范围、交付 | 中 | 高 | 影响迭代计划与测试覆盖 |
| 技术风险 | Vue 2 + Element UI 与后端 Koa 集成不稳定 | 前后端联调 | 中 | 中 | 需要提前确认接口契约 |
| 质量风险 | 无持续测试流水线，回归依赖手动验证 | 发布质量 | 中 | 高 | 容易出现高优缺陷回归 |
| 数据风险 | 数据库设计或迁移错误导致数据一致性问题 | 业务正确性 | 低 | 高 | 影响宿舍与学生档案数据 |
| 性能风险 | API 大量检索、统计时响应变慢 | 体验与可用性 | 中 | 中 | 需设计分页与索引策略 |
| 安全风险 | JWT 配置或权限控制缺失 | 系统安全 | 低 | 高 | 可能导致未授权访问 |
| 进度风险 | 关键任务延迟，如前端模块或后端接口 | 交付计划 | 中 | 中 | 需导入缓冲时间 |

## 2. 缓解措施

### 2.1 需求风险
- 通过需求评审会议明确每个功能点
- 对关键功能建立 `RTM` 并跟踪变更
- 每次变更由产品经理评估影响并更新计划

### 2.2 技术风险
- 预先完成后端接口设计文档
- 前端与后端使用统一请求规范与错误码
- 设置 mock 接口进行前端开发并行

### 2.3 质量风险
- 定义关键测试用例，并实现前端 `Jest` 单元测试
- 后端编写接口验证脚本，至少覆盖主数据流
- 使用 `eslint` 与 `prettier` 保持代码一致性

### 2.4 数据风险
- 使用数据库初始化脚本 `server/package.json` 中 `db:init`
- 设计数据迁移与回滚方案
- 重要表单操作增加事务控制和逻辑校验

### 2.5 性能风险
- 对 `GET /api/user/getStudents`、`/api/building` 等查询接口进行分页设计
- 后端限制查询条件并避免全表扫描
- 前端缓存常用列表，例如楼层、宿舍数据

### 2.6 安全风险
- 使用 `koa-jwt` 保护私有接口
- 对管理员、超级管理员操作进行角色校验
- 对所有输入字段进行参数校验与白名单过滤

### 2.7 进度风险
- 将关键路径任务纳入 `Task Set Network`
- 为每个子模块保留 15% 的时间缓冲
- 每周检查任务完成情况并调整优先级

## 3. 监控计划

- 每日跟踪任务状态，并记录未完成原因
- 定期检查测试通过率和缺陷修复进度
- 对线上运行错误进行日志分析与告警
- 对关键接口响应时间设定基准值

## 4. 管理策略

- 风险所有者：项目经理负责风险监督，技术负责人负责技术风险响应
- 风险登记：使用项目管理工具记录风险条目与处置结果
- 风险评审：每周进行风控会议，判断风险等级是否变化
- 变更控制：需求变更前必须进行影响评估，并由产品经理与项目经理签字确认

## 5. 重点风险处置

- **需求变更**：调整迭代范围、优先级或将次要需求推迟到下一版本
- **技术攻关**：对于前后端联调障碍，先搭建最小可行版本以保证核心功能可用
- **测试不足**：视情况先执行人工验收，并补偿自动化测试覆盖不足部分
- **性能问题**：定位热点接口、优化数据库索引、拆分统计查询
