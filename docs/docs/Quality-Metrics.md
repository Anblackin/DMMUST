# 质量指标（Quality Metrics）

负责人角色：测试工程师

## 1. 可用性

- **系统可用率**：目标 99.5% 以上
- **登录成功率**：正常用户登录成功率 ≥ 98%
- **页面加载时间**：关键页面首屏加载时间 ≤ 2.5 秒
- **接口响应时间**：核心 API 平均响应时间 ≤ 300ms

## 2. 功能正确性

- **需求覆盖率**：功能点测试覆盖率 ≥ 95%
- **业务关键路径通过率**：学生注册、登录、打卡、宿舍分配、评价与管理操作通过率 = 100%
- **边界条件验证**：所有输入验证与错误提示覆盖常见异常场景

## 3. 可靠性与稳定性

- **后端异常率**：生产环境错误率 < 1%（以业务异常为准）
- **页面崩溃率**：前端运行时错误 < 0.5%
- **JWT 失效处理**：Token 过期或验证失败应返回标准错误码并提示重新登录

## 4. 安全性

- **认证有效性**：所有私有 API 使用 JWT 认证，未登录访问拒绝401/403
- **输入过滤**：用户输入必须进行字段合法性校验，防止 SQL 注入与 XSS
- **密码存储**：后端密码按 `bcrypt` 加密存储，明文密码不得入库

## 5. 可维护性

- **代码静态检查通过率**：前端 `eslint --ext .js,.vue src` 通过；后端遵循 eslint 规则
- **模块化程度**：前端按组件和路由划分，后端按 controller/model/router 分离
- **文档完整性**：包含架构说明、API 接口说明、部署文档

## 6. 测试覆盖

- **单元测试覆盖率**：前端关键业务逻辑单元测试覆盖率 ≥ 60%
- **集成测试覆盖率**：后端核心接口集成测试覆盖率 ≥ 70%
- **回归测试强度**：每次发布前必须覆盖最少 10 条关键回归用例

## 7. 性能

- **构建包体积**：前端生产包体积控制在合理范围内（单页面入口含依赖 ≈ 1MB 以内）
- **数据库查询效率**：热点查询接口响应时间 ≤ 300ms
- **并发能力**：后端应支持至少 50 个并发用户场景，关键业务不会出现明显超时

## 8. 可部署性

- **运行环境一致性**：开发、测试、预发、生产环境使用统一 Node 版本 `16.20.1`
- **部署成功率**：部署后一小时内无关键故障
- **回滚方案**：发布失败时可快速恢复到上一个稳定版本

## 9. 指标追踪建议

- 每周评估一次整体质量指标
- 与项目经理同步缺陷密度、可用率、测试通过率
- 记录生产问题，并将根因反馈到开发与测试改进计划中
