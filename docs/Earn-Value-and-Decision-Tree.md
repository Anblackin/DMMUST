# 挣值分析 & 决策树（Earn Value & Decision Tree）

负责人角色：项目经理

## 1. 挣值分析概念

- **PV（计划价值）**：计划完成工作对应的预算价值
- **EV（挣得价值）**：实际完成工作对应的预算价值
- **AC（实际成本）**：实际投入的资源成本
- **SPI（进度绩效指数）**：`EV / PV`
- **CPI（成本绩效指数）**：`EV / AC`

## 2. 里程碑与预算划分

| 里程碑 | 计划完成时间 | PV（人日） | 说明 |
|---|---|---|---|
| M1 需求与设计完成 | 周 2 | 24 | 需求确认与架构设计 |
| M2 后端与模型完成 | 周 5 | 72 | 后端接口、数据库模型、权限基础 |
| M3 前端页面完成 | 周 8 | 72 | 学生端 + 管理端关键页面 |
| M4 联调与测试完成 | 周 11 | 60 | 前后端联调、测试修复 |
| M5 部署验收完成 | 周 13 | 30 | 生产构建与用户验收 |
| **总计** | - | **258** | 估算总价值 |

## 3. 进度绩效实例

### 3.1 周 5 进度评估

- 计划完成价值 PV = 120 人日
- 实际完成工作 EV = 110 人日
- 实际成本 AC = 115 人日

计算结果：
- SPI = 110 / 120 = 0.92（进度滞后）
- CPI = 110 / 115 = 0.96（成本略高）

### 3.2 判定与建议

- SPI < 1 说明当前进度低于计划
- CPI < 1 说明资源消耗高于预期
- 应优先检查关键模块进度瓶颈，并适度降低迭代范围或增加测试并行度

## 4. 决策树

本决策树围绕“是否继续按原计划推进”做出三种备选方案。

### 4.1 方案 A：继续推进，增加资源

- 前提条件：核心模块开发正常，可通过额外人力补足延迟
- 风险：沟通成本上升，质量控制难度加大
- 适用场景：需求稳定、技术风险低

### 4.2 方案 B：压缩非核心功能，优先核心路径

- 前提条件：进度滞后，且产品可接受先交付核心功能
- 风险：次要功能推迟上线，客户期望需沟通
- 适用场景：项目时间紧张、风险高于可控范围

### 4.3 方案 C：重置设计与关键路径

- 前提条件：发现架构或接口设计重大问题，导致开发效率显著下降
- 风险：短期内会丢失部分进度，但长期能提高稳定性
- 适用场景：技术风险或质量风险对项目构成严重威胁

## 5. 决策树节点

1. 当前 SPI 是否 ≥ 0.95？
   - 是 → 继续原计划（方案 A）
   - 否 → 进入下一节点
2. 关键功能是否完成率 ≥ 70%？
   - 是 → 采用方案 B，保留核心功能上线
   - 否 → 进入下一节点
3. 是否存在技术或架构风险？
   - 是 → 采用方案 C，重新评估设计
   - 否 → 方案 B，集中资源完成核心模块

## 6. 监控与调整建议

- 每个里程碑结束时计算 PV、EV、AC、SPI、CPI
- 当 `SPI < 0.9` 或 `CPI < 0.9` 时，启动一次专项风险评审
- 若关键功能未达到 `70%`，优先采用 `方案 B`，将非核心任务退回下一迭代
- 对于已上线功能，继续执行回归测试以保证质量
